# 0.4.1 Quick Wins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the five quick-win gaps that the blind 0.4.0 reviews found. Rule detection misses common phrasings, statement text is not compared with its quote, "keep it flagged" is asked again every session, clarifications hit a redraft dead end, and `kb todo` is slow on large repos.

**Architecture:** These are small, independent changes to existing modules. No new record types. Decisions reuse the 0.4.0 decisions file (`kb/eval/decisions.yaml`, in canonical form, with entries pinned).

**Tech Stack:** Python ≥3.12, uv, Typer, pydantic v2, pytest.

**Spec:** The blind review reports, summarised in the evaluation artifact under "0.4.1 · quick wins". The findings this plan implements:
- **Completeness review, gaps 1, 4, 5, 6, 7.** Cue list misses will/can/mandatory/forbidden/number words. One sentence with several rules, and list lead-ins. No statement-vs-quote modal/number check. No duplicate detection.
- **Smoothness review, friction 2, 3, 4.** The redraft brief has no old-vs-new diff. Clarification triage is rejected as out of scope. "Keep it flagged" is never remembered.
- **Design review, problem 3.** One `git show` per file.

## Global Constraints

- Backward compatible. A 0.4.0 repo still passes `kb check` with warnings only. New checks are warnings in `kb check` and escalate to errors only for records drafted in the current ingest/redraft range, using the existing `gate_drafts` escalation.
- Every untrusted text goes through `inline_code` / `_fence` / `_md`. No document text appears in printed commands.
- Quote matching goes only through `find_quote` / `located_quotes`. Cue detection goes only through `kb.sources.sentences.cues`.
- Exit codes: 0 means ok, 1 a gate failure, 2 a usage, config or tool error.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01FU26Rg1DsNpsAtdAuPuQzD`.

## Review Focus

1. Wider cues must not flood coverage with noise. These must stay cue-less: "can" in "you can find the docs at …", "will" in descriptive future text, and page or section numbers. (Task 1, `test_wider_cues_stay_quiet_on_descriptive_text`.)
2. Clause splitting must keep exact offsets, so that `text_md[s.start:s.end] == s.text` still holds for every unit. (Task 1, `test_clause_units_slice_exactly`.)
3. A kept flag must come back when the record or its cited segment changes. A forged hand-written "keep" must be checked like any other decision. (Task 3, `test_kept_flag_returns_when_record_changes`.)
4. Batch git reading must handle binary blobs, symlink entries, paths with spaces or newlines, and an empty tree. (Task 5, `test_batch_read_matches_show_for_odd_paths`.)
5. The redraft diff in the brief shows untrusted old and new text, so it must be fenced. (Task 4, `test_redraft_brief_diff_is_fenced`.)

### Task 1: Wider rule cues, clause units, list lead-ins

**Files:** Modify `src/kb/sources/sentences.py`. Test `tests/sources/test_sentences.py`.

**Interfaces:** `cues()`, `sentences()` and `Sentence` keep their signatures. Units can now be clauses.

- [ ] **Step 1: Write the failing tests.**
  - `test_wider_cues`:
    - "Invoices will be issued on the 1st." gets `must`.
    - "Admins can remove seats." gets `may`.
    - "Exports are mandatory." gets `must`.
    - "Deleting invoices is forbidden." gets `must_not`.
    - "Refunds are not permitted." gets `must_not`.
    - "The system shall ensure backups." gets `must`.
    - "within fifteen minutes" gets `limit` and `number`.
    - "15 min" gets `number`.
    - "24/7" gets `number`.
    - "AES-256" gets `number`.
  - `test_wider_cues_stay_quiet_on_descriptive_text`: these get no modality cue.
    - "You can find the guide at docs.acme.io."
    - "This document will describe the billing flow."
    - "See section 3 on page 2."
    - Rule: "can" or "will" counts only when its subject is not "you", "we" or "this document/section/guide".
  - `test_clause_units`: "The service must retry three times; it must email the owner, and refunds above $500 require approval." becomes 3 units, split on "; " and on ", and" / ", or" followed by a clause that has its own modal or verb cue.
  - `test_clause_units_slice_exactly`.
  - `test_list_items_inherit_lead_in_cue`: "The system must:\n- log every change\n- keep logs 90 days" gives each item `must`.
  - `test_more_abbreviations`: "Dr. Smith approves. Acme Inc. pays." becomes 2 units. Add "dr.", "mr.", "mrs.", "ms.", "inc.", "ltd.", "co.", "st." to `_ABBREVIATIONS`.
- [ ] **Step 2: Run the tests and confirm they fail.**
- [ ] **Step 3: Implement the changes.**
  - Extend `NORMATIVE_CUES`:
    - `must` adds will, mandatory, ensure(s) and is/are to.
    - `must_not` adds forbidden, not permitted, prohibited and never.
    - `may` adds can, optional and permitted.
    - `number` adds number words one through twenty, hundred and thousand, plus `\d+\s?(min|h|hrs?|s|ms)\b`, `24/7` and `[A-Z]+-\d+` (except kb IDs).
  - Apply the subject exclusion for can and will.
  - Split clauses inside a unit at "; " and at ", and"/", or"/", but" when the remainder has a modal cue.
  - A list item inherits the modal cues of a preceding lead-in line that ends with ":".
- [ ] **Step 4: Run the tests.** Run `uv run pytest tests/sources tests/gates tests/eval -q`. Coverage expectation counts in fixtures may change, so update them and list each change.
- [ ] **Step 5: Commit** with the message `feat(sources): wider rule cues, clause units, list lead-ins`.

### Task 5: Batch git reads

**Files:** Modify `src/kb/gitfiles.py` (`read_tree_files` at about line 217). Test `tests/test_gitfiles.py` (or wherever gitfiles is tested) and `tests/test_todo_perf.py`.

**Interfaces:** `read_tree_files(root, ref, prefix) -> dict[str, bytes]` keeps its signature and its output. It does one `git ls-tree -r -z` and one `git cat-file --batch` stream, with each request on its own line as `<ref>:<path>`. Because a path can contain a newline, use `git cat-file --batch` with object ids from `ls-tree -z` (without `--name-only`) rather than paths.

- [ ] **Step 1: Write the failing tests.**
  - `test_batch_read_matches_show_for_odd_paths`: cover paths with spaces, a newline, unicode and a leading dash, plus a binary blob, a symlink entry (its target bytes, as `git show` gives them) and an empty prefix. The result must equal the old per-file implementation, kept as a test helper.
  - `test_read_tree_files_spawns_two_processes`: monkeypatch the subprocess runner and count calls.
  - `test_todo_perf` adds a case: a 300-requirement KB runs `kb todo` under 2.5 s, where the generous bound is 3x the measured time.
- [ ] **Step 2: Run the tests and confirm they fail.**
- [ ] **Step 3: Implement as specified.**
